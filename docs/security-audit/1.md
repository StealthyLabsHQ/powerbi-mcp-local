# Summary

Introduced: the new SSE transport exposes the existing powerful tool surface over HTTP without any authentication or authorization checks. The pre-existing tools were already dangerous by design for a trusted local stdio client, but this commit changes the trust boundary by making them reachable through an HTTP transport.
Before this commit the MCP server only ran over stdio, limiting access to a client that could spawn or communicate with the local process. This commit adds `--transport sse` and starts an HTTP/SSE MCP endpoint with only a port parameter. The server registers numerous high-impact tools, including DAX query execution, measure deletion, model refresh, Power Query mutation, and Excel file writes. There is no bearer token, origin check, access-control middleware, tool filtering, or read-only mode in the added SSE path. If the FastMCP SSE listener is reachable beyond the intended local client, an unauthenticated attacker can invoke the full MCP tool surface to read model data, alter or corrupt the Power BI model, trigger refreshes, and modify local Excel workbooks accessible to the server process.

def main() -> None:
    """Entry point — supports stdio (default) and sse transport."""
    import argparse

    parser = argparse.ArgumentParser(description="Power BI Desktop MCP Server")
    parser.add_argument(
        "--transport",
        choices=["stdio", "sse"],
        default="stdio",
        help="MCP transport: stdio (CLI tools) or sse (web/IDE clients)",
    )
    parser.add_argument(
        "--port",
        type=int,
        default=8765,
        help="Port for SSE transport (default: 8765)",
    )
    args = parser.parse_args()

    if args.transport == "sse":
        mcp.run(transport="sse", sse_params={"port": args.port})
    else:
        mcp.run(transport="stdio")
